# AgenticThesis v1.0 Execution Plan

Status: superseded by the v1.1 alpha implementation on `main`; retained as the original design record

Starting baseline: `main` at `183b64f`

Product promise: **Every material company disclosure is discovered, preserved, routed to the relevant thesis claims, and kept non-authoritative until Human Review.**

Implementation checkpoint on 2026-09-04:

- Slice 0 complete: the deterministic suite is bounded and green (`23 passed in 5.63s`); every pre-v1.0 database is rejected without modification.
- Slice 1 core complete: typed events, immutable byte artifacts, exact artifact retrieval, parser outcomes, collection attempts, and per-artifact fetch failures are persisted through the public engine interface.
- Slice 2 partial: SEC recent/history traversal, filing-index parsing, primary documents, selected exhibits/XML, partial failure handling, and a persisted configured-form Radar decision are implemented. Amendment linking and the full SEC fixture matrix remain.
- Slices 3-7 remain open. The current Radar policy preserves v0.9 behavior; falsifier-driven relevance routing is not yet implemented.

## 1. Release boundary

v1.0 expands AgenticThesis from an SEC-primary-document monitor into an evidence radar. It does not turn the engine into a news summarizer or an investment-advice system.

The release is complete when it can:

1. discover every filing event reported by SEC submissions data for a configured CIK, including amendments and older submissions pages;
2. preserve the filing index and relevant original artifacts, rather than only the primary HTML body;
3. ingest official issuer HTML, PDF, presentation, press-release, and official transcript artifacts from explicitly configured IR locations;
4. extract native PDF text and use bounded, opt-in OCR when a document has no usable text layer;
5. retain source identity, authority, timestamps, hashes, retrieval attempts, parse status, and exact citation locators;
6. route each new event to a persisted Radar Inbox as `needs_review`, `digest`, or `ignored`;
7. start the existing disclosure-bound thesis workflow only for `needs_review` events;
8. keep secondary news as a verification lead that cannot independently authorize a thesis revision.

The authoritative path remains:

```text
source event
  -> immutable source artifact(s)
  -> normalized disclosure
  -> source-addressable evidence
  -> proposed thesis delta
  -> Human Review
  -> immutable thesis revision
```

## 2. Current baseline and concrete gaps

v0.9 already provides the part that should be reused:

- one `disclosure_id` per run;
- structure-aware SEC HTML parsing;
- claim and falsifier retrieval;
- exact citation validation;
- persisted runs, events, checkpoints, reviews, immutable revisions, and compare-and-swap commits;
- one daily SEC monitor per thesis with accession/content deduplication and retry after collection failure.

The v1.0 gaps are concentrated at the ingestion and routing seams:

| Current v0.9 behavior | v1.0 gap |
|---|---|
| Reads only `filings.recent` | Older SEC submission files are not traversed. |
| Downloads only `primaryDocument` | Filing index, exhibits, ownership XML, and other filing artifacts are not retained. |
| Stores one large text field | No immutable byte artifact, media type, artifact hash, accepted time, form/item metadata, or parser version. |
| Parser assumes HTML/TXT | No PDF page extraction, OCR state, or page-addressable citation. |
| One SEC-specific monitor table | No official IR page, feed, document, or transcript monitoring. |
| Every imported filing starts analysis | No persisted Radar Inbox or relevance gate. |
| `last_error` records only the latest SEC failure | No queryable collection-attempt history or per-artifact parse failure. |
| No secondary-source distinction | A news lead cannot be represented without pretending it is authoritative evidence. |

## 3. Minimal domain additions

Keep `AgenticThesisEngine.run(run_id, thesis_id, disclosure_id)` and the current workflow interface unchanged. Add the following persisted concepts before adding another collector:

- `DisclosureEvent`: one filing, issuer release, presentation, or call; carries publisher, authority, event type, external ID, published/accepted time, amendment relationship, and discovery time.
- `SourceArtifact`: immutable fetched bytes plus URL, media type, SHA-256, retrieved time, parser name/version, parse status, page/character locator map, and role such as primary document, exhibit, filing index, presentation, or transcript.
- `CollectionAttempt`: source, monitor, cursor before/after, success/failure, timestamps, and error. A failure never means “no new evidence.”
- `RadarEntry`: event, thesis, outcome, reason codes, matched claim/falsifier IDs, and optional run ID.

`DisclosureDocument` remains the normalized input to the existing run path during v1.0. It gains links to its event and artifacts instead of being replaced throughout the workflow.

Do not add a public provider plugin system. SEC and IR collectors should call one internal ingestion function; introduce a wider collector interface only after a third independently maintained integration exists.

## 4. Source authority policy

| Tier | Examples | Allowed use |
|---|---|---|
| A — regulator | SEC EDGAR filing index, primary documents, exhibits, ownership XML, XBRL | May support a thesis delta when exact evidence is available. |
| B — issuer official | IR release, report, presentation, event page, official transcript | May support a thesis delta with explicit issuer provenance. |
| C — reliable secondary | Licensed or publicly accessible reputable news | Radar lead only until corroborated by Tier A/B evidence; otherwise clearly labeled secondary evidence. |
| D — attention signal | Social, forums, trends | Out of v1.0. |

Publisher authority must be data, not prompt text. The model cannot promote a Tier C source into Tier A/B.

## 5. Execution slices

Each slice should be independently reviewable and leave one runnable contract test. Do not start a later slice while an earlier acceptance gate is red.

### Slice 0 — restore a bounded green baseline

Deliverables:

- identify why the current full deterministic suite stalls after 17 tests;
- retain the existing SEC monitor behavior and public engine contract;
- define the v1.0 fixture set and reject every pre-v1.0 SQLite database without modifying it.

Acceptance:

- all deterministic tests pass within an agreed local runtime budget;
- no external model or network call is required;
- every pre-v1.0 database is rejected without modification; no migration or compatibility layer is implemented.

### Slice 1 — evidence ingestion core

Deliverables:

- add the four persisted concepts above and a single internal `ingest_event(...)` path;
- save artifact bytes and metadata in SQLite, keyed by hash; move large blobs to content-addressed files only if measured corpus size requires it;
- preserve byte hashes and provenance before parsing;
- extend chunks/evidence with `artifact_id` and page or character locator;
- record collection and parsing failures as durable outcomes.

Acceptance:

- the same bytes are stored once and can be referenced by multiple events;
- changed bytes at the same URL create a new artifact version;
- an unavailable or unparseable artifact remains visible and cannot produce “no evidence”;
- every accepted evidence quote resolves exactly to one stored artifact locator;
- existing manual HTML/TXT ingestion and run/review/revision contracts remain green.

### Slice 2 — complete SEC event and artifact collection

Deliverables:

- traverse `filings.recent` and SEC-provided older submissions files using a durable cursor;
- bind by normalized CIK and accession;
- persist form, filing date, accepted timestamp, primary document, filing index, amendment form, and related accession when deterministically available;
- read the filing index and fetch human-readable primary documents and exhibits;
- retain structured XML/XBRL artifacts even when semantic extraction is not yet implemented;
- classify common form families before model use.

Required fixture families:

- 10-K/10-Q and amendments;
- 8-K with at least one exhibit;
- DEF 14A;
- Forms 3/4/5 XML;
- Schedule 13D/13G and amendments;
- 13F filing and information table;
- one uncommon form that is discovered and retained without a custom semantic parser.

Acceptance:

- every fixture filing is discovered once by accession;
- all relevant artifacts have stable hashes and SEC URLs;
- amendments are separate events linked to the filing they amend when the relationship is available;
- unsupported forms are retained and surfaced, not silently dropped;
- a failed exhibit does not erase a successfully fetched primary document, and the partial failure is visible.

### Slice 3 — PDF and bounded OCR

Deliverables:

- select the smallest native-PDF parser that passes the checked-in fixture benchmark;
- retain page boundaries and exact quote-to-page mapping;
- detect encrypted, malformed, and image-only PDFs;
- add opt-in OCR with concurrency `1`, explicit page/file limits, no automatic model download, and a durable `needs_ocr`/failure state when unavailable.

Acceptance:

- native-text PDFs produce exact page-addressable citations;
- a scanned fixture follows the OCR path and produces page-addressable text;
- exceeding OCR limits stops safely and remains visible in the Radar Inbox;
- tables or layout that cannot be reconstructed are marked as unknown instead of converted into confident evidence.

### Slice 4 — official IR and earnings-call monitoring

Deliverables:

- configure explicit issuer-owned IR page/feed URLs per thesis;
- use HTTP metadata and content hashes to detect changes in static HTML, RSS/Atom, and linked documents;
- ingest official releases, reports, presentations, event pages, and official text transcripts through `ingest_event(...)`;
- store the page version that produced each discovered link.

Acceptance:

- unchanged content creates no event;
- a changed release or newly linked PDF creates one event with publisher provenance;
- removing or replacing a document remains observable;
- when no official transcript exists, record that state and stop. Do not download audio, install speech models, or start local transcription.

Initial ceiling:

- static HTML/feed/document discovery only;
- no headless-browser crawler, anti-bot bypass, generic site spider, or audio transcription in v1.0.

### Slice 5 — thesis-driven Radar Inbox

Deliverables:

- reuse existing claim statements and `falsifiers` as routing queries;
- deterministically apply duplicate, authority, form/item, parse-status, and source rules before any model call;
- persist `needs_review`, `digest`, and `ignored` with reason codes;
- launch the existing thesis-delta workflow only from `needs_review`;
- expose inbox, source status, failures, matched claims/falsifiers, and run links through the engine, HTTP interface, and browser UI.

Initial routing policy:

- `needs_review`: extractable Tier A/B evidence matches a claim/falsifier or a configured high-impact SEC form/item rule;
- `digest`: a new Tier A/B event is preserved but does not cross the evaluated relevance threshold;
- `ignored`: an exact duplicate or an explicit human decision; automated low-confidence suppression should use `digest`, not `ignored`;
- Tier C news: `digest` with `needs_verification`, never an automatic thesis run.

Acceptance:

- replaying collection does not duplicate inbox entries or runs;
- collection/parse failures are visible beside successful events;
- every `needs_review` entry links to its immutable artifacts and resulting run;
- changing the routing policy cannot rewrite historical decisions; it produces a new evaluated decision version;
- inbox routing passes the versioned fixture evaluation before becoming the default.

### Slice 6 — reliable secondary-news leads

Deliverables:

- support explicitly configured RSS/Atom or licensed endpoints from selected publishers;
- retain source URL, publisher, timestamp, headline, retrieval rights/status, and content hash;
- route news only as a verification lead and search Tier A/B sources for corroboration.

Acceptance:

- a news item alone cannot create or approve a thesis delta;
- inaccessible or non-retainable article bodies remain metadata-only leads;
- source terms, robots policy, and content-retention limits are respected;
- no generic web-wide news crawler ships in v1.0.

### Slice 7 — evaluation, recovery, documentation, and release

Deliverables:

- add versioned fixtures covering all source and failure cases above;
- measure discovery completeness, duplicate suppression, exact citation resolution, Radar routing, and recovery after interruption;
- verify restart/resume between fetch, artifact save, parse, routing, run launch, and Human Review;
- update README/README_ZH, architecture HTML/SVG, public models, and release notes together.

Release gates:

- 100% fixture event discovery for the checked-in SEC/IR corpus;
- 100% exact quote-to-artifact locator validation for accepted evidence;
- zero duplicate runs under replayed collection fixtures;
- zero Tier C-only authoritative thesis revisions;
- all failure states survive restart and remain queryable;
- all deterministic tests pass within the local runtime budget;
- any model-based Radar metric is published only from a reproducible evaluation run.

## 7. Explicit non-goals

- Buy/Sell/Hold recommendations, valuation, position sizing, or portfolio execution;
- social sentiment, Reddit, Wikipedia attention, or web-wide crawling;
- automatic trust in headlines, metadata, or model-generated citations;
- local audio transcription;
- distributed queues, microservices, a general provider marketplace, or multiple LangGraph subgraphs;
- semantic normalization for every SEC form before the generic artifact path has proved complete;
- email/push notification delivery before real users demonstrate a need for off-app interruption.

## 8. First implementation checkpoint

The first checkpoint is not another collector. It is a vertical fixture proving:

```text
8-K event
  -> filing index + primary HTML + exhibit PDF stored immutably
  -> exact HTML/PDF citations
  -> one persisted collection attempt
  -> one Radar decision tied to a falsifier
  -> one existing disclosure-bound run
  -> Human Review
  -> immutable revision
```

Once this passes through the public engine interface and survives restart/replay, the same ingestion path can be used by the remaining SEC forms and official IR sources.
